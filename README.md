# portfolio

A Flutter starter app with the basics already wired up: flavors, dependency
injection, networking, local storage, localization (English and Myanmar),
routing and a light/dark theme. Build features on top of it instead of
starting from `flutter create` every time.

## Requirements

- Flutter **3.47.9** (stable), Dart **3.13.7** or newer
- Xcode for iOS, Android Studio / Android SDK for Android
- VS Code is optional. Launch configs for every flavor are in `.vscode/launch.json`

Check your setup with:

```sh
flutter --version
flutter doctor
```

## First-time setup

```sh
git clone <repo-url>
cd portfolio

flutter pub get
flutter gen-l10n
dart run build_runner build
```

Run the last two again whenever you change `.arb` files or any class with
`@injectable`, `@freezed` or `@JsonSerializable` annotations. Generated files
(`*.g.dart`, `*.freezed.dart`, `lib/src/di/injector.config.dart`) are not
committed, so a fresh clone won't compile until `build_runner` has run.

While you're working on generated code, keep it running in watch mode instead:

```sh
dart run build_runner watch
```

## Running the app

There are two flavors, and you always have to pick one:

| Flavor | App name      | Bundle / application id      | API                           |
| ------ | ------------- | ---------------------------- | ----------------------------- |
| `uat`  | Romanbot4 UAT | `com.romanbot4.portfoliouat` | `NetworkConfig.stagingDomain` |
| `prod` | Romanbot4     | `com.romanbot4.portfolio`    | `NetworkConfig.prodDomain`    |

```sh
flutter run --flavor uat
flutter run --flavor prod
```

Builds:

```sh
flutter build apk --flavor prod
flutter build appbundle --flavor prod
flutter build ipa --flavor prod
```

Both flavors can be installed on the same device side by side.

## Project structure

```
lib/
├── main.dart               Entry point: sets the flavor, configures DI, runs the app
├── app.dart                MaterialApp.router (theme, localization, router)
├── flavors.dart            Flavor enum + F (generated by flavorizr)
└── src/
    ├── config/             Static app config (defaults, network, per-flavor base URL)
    ├── core/               Framework-free building blocks
    │   ├── data_state/     Result<T>
    │   ├── exceptions/     CoreError types + IExceptionMapperService
    │   ├── failures/       Failure types shown to the UI
    │   └── usecase/        UseCase<T, P> base class
    ├── di/                 get_it + injectable setup
    │   └── third_party_modules/   Providers for Dio, SharedPreferences, etc.
    └── features/
        └── commons/        Shared across features
            ├── domain/     Interfaces, use cases
            ├── data/       Implementations
            └── presentation/
                ├── design/      AppColors, AppTypography, AppTheme
                ├── extensions/  BuildContext extension like context.something
                ├── router/      go_router based router
                ├── services/    SnackShower
                └── ui/          Snacks and other prompts
```

New features go in `lib/src/features/<feature>/`, following the same
`domain / data / presentation` split as `commons`.

### Conventions

- **Use cases** extend `UseCase<TData, TParam>` and return a `Result`. Errors
  thrown inside `handle()` are mapped to a `Failure`, so callers never need
  a `try/catch`.
- **Interfaces** are prefixed with `I` (`ILocalStorage`, `IAppRouter`), and
  implementations are registered with `@Injectable(as: …)` or in a DI module.
- **Strings** come from `context.localizations.someKey`. Don't hardcode
  user-facing text.
- **Colors and text styles** come from the theme (`context.theme`,
  `context.textTheme`). Use `AppColors` directly only when no theme role fits.

## Localization

- Source files: `l10n/en.arb` (template) and `l10n/my.arb`
- Output: `lib/src/features/commons/domain/services/i18n/`
- Config: `l10n.yaml`

To add a string, put it in `en.arb`, add the Myanmar translation to `my.arb`,
then run `flutter gen-l10n`. Missing Myanmar strings fall back to English and
are listed in `to_translate.txt`.

## Theming and fonts

`AppTheme` builds the light and dark `ThemeData` from `AppColors` and
`AppTypography`. To rebrand, change `primary` / `secondary` in
`app_colors.dart`, and that's usually enough to get started.

Fonts are bundled in `assets/fonts/`:

- **Roboto** for Latin text
- **Noto Sans Myanmar** for Myanmar text, picked automatically when the locale is `my`
