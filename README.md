# jdonuts

The J'Donuts customer app code test: phone sign-in and registration, an
offline-first Home and Product detail backed by a local database, and an
animated Rewards screen. It runs on Android and iOS.

It's also built as a reusable starter, with flavors, dependency injection,
networking, local storage, localization (English and Myanmar), routing and a
light/dark theme already wired up.

## For reviewers

```sh
flutter pub get
flutter gen-l10n
dart run build_runner build
flutter run
```

- **No flags needed:** `flutter run` uses the **`prod`** flavor by default.
- **Data:** Home, Product detail and Rewards load live data from the hosted mock
  API (`https://jdonuts-mock.netlify.app/api`), with the bundled seed data as the
  offline fallback.
- **Sign-in:** uses the **on-device fake** backend, so registering and logging
  in work with no server and in airplane mode.
- **OTP code:** **`123456`**.

## First-time setup

```sh
git clone <repo-url>
cd jdonuts

flutter pub get
flutter gen-l10n
dart run build_runner build
```

Run the last two again whenever you change `.arb` files or any class with
`@injectable`, `@freezed`, `@JsonSerializable`, `@RestApi` or a Drift table.
Generated files (`*.g.dart`, `*.freezed.dart`, `lib/src/di/injector.config.dart`)
are not committed, so a fresh clone won't compile until `build_runner` has run.

While you're working on generated code, keep it running in watch mode instead:

```sh
dart run build_runner watch
```

## Running the app

There are two flavors. **`prod` is the default**, so `flutter run` and
`flutter build` without `--flavor` use it.

| Flavor | App name    | Bundle / application id    | API                           |
| ------ | ----------- | -------------------------- | ----------------------------- |
| `uat`  | JDonuts UAT | `com.romanbot4.jdonutsuat` | `NetworkConfig.stagingDomain` |
| `prod` | JDonuts     | `com.romanbot4.jdonuts`    | `NetworkConfig.prodDomain`    |

```sh
flutter run --flavor uat
flutter run --flavor prod
```

Builds:

```sh
flutter build apk --release --flavor prod
flutter build ios --simulator --flavor prod
flutter build ipa --flavor prod
```

Both flavors can be installed on the same device side by side. Only `uat` is
allowed to use plain HTTP, so it can reach the mock server on your local network.

> If a release build stops with
> `package dev.flutter.plugins.integration_test does not exist`,
> clean first:
>
> ```sh
> flutter clean && flutter pub get && dart run build_runner build
> ```
>
> The integration test run leaves a generated `GeneratedPluginRegistrant.java`
> that registers the `integration_test` plugin. It's a know issue but just in case.

### Fake OTP code

The OTP code is **`123456`**. Any other code fails, and three wrong codes lock
entry until you resend.

### Auth backend

Auth uses the **on-device fake** by default, as the brief asks. Each step waits
about a second, users are stored locally, and it works in airplane mode. To use
the mock server's `/auth` endpoints instead:

```sh
flutter run --flavor uat --dart-define=AUTH_BACKEND=remote
```

### Mock server (optional)

Home, Product detail and Rewards refresh from the mock server's versioned
`/v1/...` endpoints, which return a `{data, error, meta}` envelope. The server is
optional. Without it the app shows the bundled seed data and stays usable.

- **`prod`** uses the hosted mock API at `https://jdonuts-mock.netlify.app/api`
  (a Netlify Function, with images on Netlify's CDN).
- **`uat`** uses the same server run locally (`npm start` or Docker on port 3000,
  `NetworkConfig.stagingDomain`).

Every feature uses the same `domain / data / presentation` split. Feature
domains (`auth`, `home`, `product`, `rewards`, `cart`) are pure Dart, with no
Flutter imports. Presentation depends on domain, and data implements domain's
interfaces, so replacing the fake auth or the mock server never touches the UI.

## Authentication

**Flow.**

- Register: onboarding > phone > OTP > name > date of birth > welcome > home
- Log in: phone > OTP > home

After the OTP is verified, the router's guard picks the next screen from the
session (no name yet, no date of birth, or complete).

**Validation** (pure domain functions in `auth/domain/validators`):

- **Phone:** after +95, 09 Myanmar Phone Number Normalization
- **OTP:** 6 digits using regex
- **Name:** First name require. Last name is optional.
- **Date of birth:** a real calendar date, not in the future, age 13 or older.

**Session and logout.** The token is stored using secure storage and is cached in
memory. Smart token refresh and replay using my reusable `AuthInterceptor`.
Being offline never signs you out. The session ends only when the server
refuses the refresh token, and then the app goes back to onboarding with one
message. Settings has a Log out row with a confirmation sheet, and logging out
also clears the cart.

## State management

I will use BLoC (specifically Cubit). States are explicit freezed classes, cubits
can be tested without any widgets, and `SessionCubit`'s stream drives the
router's redirect directly.
Also I prefer BLoC over Riverpod due to loose couple integration with flutter's original Widgets :)

Dependency injection is `get_it` + `injectable`. No services are created
inside widgets.

## Offline strategy

The local database is the single source of truth. The UI only ever reads from
it, and the network only refreshes it.

- **Database:** Drift (SQLite) in `commons/data/database/app_database.dart`.
  Tables for the member, shops, menu sections, menu items, section items and
  challenges.
- **Versioned migrations:** schema version 3. Version 2 added the product
  description, and version 3 added challenges.
- **Seed on first launch:** `assets/seed/` holds JSON snapshots of the home
  feed, product descriptions, member and challenges. Their images are bundled
  in `assets/seed/images/`, so a first launch with no network still shows
  everything.
- **Refresh:** repositories fetch from the mock server and write into the
  database in one transaction, and the screens update through Drift streams.
  This happens:
  - when a screen opens;
  - when the network comes back;
  - on pull-to-refresh (Home).

  A failed refresh keeps the cached data.

- **Connectivity:** `connectivity_plus` plus a real reachability check (a short
  request to the API). Home shows a small offline banner.
- **Images:** `cached_network_image` keeps server images on disk, with a
  shimmer placeholder and an error state.
- **One member record:** Home and Rewards read the same `members` row.
- **Network:** Dio with 8-second timeouts, `AuthInterceptor` (token and
  refresh), `RetryInterceptor` (retries GET requests on connection errors and
  timeouts, up to 2 times) and TalkerDioLogger in debug builds.

Durations and curves live in one file: `commons/presentation/design/app_motion.dart`.
Every animation respects Reduce Motion (`MediaQuery.disableAnimations`).

| Registration steps | Slide and fade between steps; the progress ring animates 25% > 50% > 75% > 100%, then turns into a check                                                                                                                      |
| Inputs             | Focus and error outlines; OTP boxes shake and clear on a wrong code                                                                                                                                                           |
| Buttons            | Scale on press; Continue turns into a spinner while loading                                                                                                                                                                   |
| Welcome            | Donut tiles slide in staggered, then the title fades up                                                                                                                                                                       |
| Home               | Shimmer skeletons; sections enter staggered; shop banners auto-play                                                                                                                                                           |
| Product            | Hero image from the tile; the quantity number animates on change                                                                                                                                                              |
| Cart               | Floating cart bar pops up after adding                                                                                                                                                                                        |

## Testing

```sh
flutter analyze
flutter test
flutter test integration_test --flavor uat
```

- **Unit tests:** validators, use cases, `AuthInterceptor`, `RetryInterceptor`,
  repositories on an in-memory Drift database, database migrations, product
  detail quantity and total, challenge progress.
- **Widget tests:** login and registration validation (phone, OTP wrong code
  and lock, name, date of birth).
- **Integration test:** Register > Home > Product detail, on a simulator or
  device, using the fake auth backend. It clears the app's saved session and
  local preferences before it starts.

**After running the integration test, clean before a release build.** The run
regenerates `GeneratedPluginRegistrant.java` with the `integration_test` plugin.
That plugin is a dev dependency, which release builds leave out, so
`flutter run --release` / `flutter build apk --release` then fail with
`package dev.flutter.plugins.integration_test does not exist`. Run:

```sh
flutter clean && flutter pub get && dart run build_runner build
```

The file is generated and gitignored, so nothing needs committing.

## Conventions

- **Use cases** extend `UseCase<TData, TParam>` and return a `Result`. Errors
  thrown inside `handle()` are mapped to a `Failure`, so callers never need
  a `try/catch`.
- **Interfaces** are prefixed with `I` (`ILocalStorage`, `IAppRouter`), and
  implementations are registered with `@Injectable(as: …)` or in a DI module.
- **Strings** come from `context.localizations.someKey`. Don't hardcode
  user-facing text.
- **Colors and text styles** come from the theme (`context.theme`,
  `context.textTheme`). Use `AppColors` directly only when no theme role fits.
- **App Design widgets** are named `StyledSomething` and live in
  `commons/presentation/widgets`.
- **Design Systems** are defined from `AppInsets` (padding), `AppSpacing` (gaps),
  `AppRadius` and `AppMotion`. No magic numbers in widgets.
- **Design Systems** are defined under
  `commons/presentation/design` as simple abstract namespace classes.

## Localization

- Source files: `l10n/en.arb` (template) and `l10n/my.arb`
- Output: `lib/src/features/commons/domain/services/i18n/`
- Config: `l10n.yaml`

To add a string, put it in `en.arb`, add the Myanmar translation to `my.arb`,
then run `flutter gen-l10n`. Missing Myanmar strings fall back to English and
are listed in `to_translate.txt`.

## Theming and fonts

`AppTheme` builds the light and dark `ThemeData` from `AppColors` and
`AppTypography`. To rebrand, change `primary` / `secondary` in
`app_colors.dart`, and that's usually enough to get started.

Fonts are bundled in `assets/fonts/`:

- **General Sans** for body and UI text
- **Menco** for display, headings and large titles
- **Noto Sans Myanmar** for all Myanmar text

Feature images live next to their feature's resources (`AuthImages`,
`HomeImages`, `AppImages`, `AppIcons`).

## Known gaps

- **Unregistered numbers on log in:** logging in with a number that was never
  registered doesn't yet show the "register instead" message.
- **Flutter imports in shared code:** feature domains have no Flutter imports,
  but `core/usecase` (`kDebugMode`) and parts of `commons/domain` (`Locale`,
  `RouterConfig`) still do. It was an intended design choice for better development experience.
- **Tier names:** I only found the Gold, Silver and Bronze resouces to showcase my app so the Rewards ladder show those rather than Silver, Gold and Platinum from the design.
- **Display only:** social sign-in, Terms and Privacy, Explore now, Order online,
  Check out, Earn, the Gift tab and the Order and Wallet tabs.
